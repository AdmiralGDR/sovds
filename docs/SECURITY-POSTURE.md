# Security posture (IP Shield)

Принято 2026-08-08 после попытки присвоения наработок третьей стороной.
Область действия: `crates/`, `deploy/router/`, весь этот репозиторий.
НЕ распространяется на соседние семейные проекты (sovmr/sovscale/Aetherium/
Finances) — там решения принимаются отдельно, в своих репозиториях.

## Принято как есть

1. **Копирайт-заголовок в каждом ключевом файле.** Все `crates/*/src/**/*.rs`
   и `deploy/router/*` несут `// Copyright (C) 2026 AdmiralGDR. Licensed
   under AGPLv3.` + SPDX-идентификатор.
2. **AGPLv3 вместо MIT/Apache-2.0.** Ранее (см. `sovds-toolkit-refactor`
   в памяти) лицензия была намеренно permissive — расчёт был на лёгкую
   встраиваемость в сторонние проекты. Приоритет сменился: сейчас важнее
   юридически связать любого, кто возьмёт код в прод, обязательством
   раскрыть свои изменения (в т.ч. через сеть — Affero-пункт). Это
   осознанная смена решения, а не забытьё старого. `sovds` остаётся
   доменно-агностичным тулкитом технически — просто теперь copyleft.
3. **GPG-подписанные коммиты, ключ отдельный от других проектов.**
   Fingerprint `012C12AACD117A5E206F6E30108622CBDE485096`, uid "Sovereign
   Brain (sovds/sovereign-core signing key, project-scoped)". Настроено
   ЛОКАЛЬНО в `.git/config` этого репозитория (`user.signingkey`,
   `commit.gpgsign=true`) — глобальный `~/.gitconfig` не тронут, ключ
   RedstoneTeam/Aetherium (используется другими проектами) не затрагивается.
4. **SHA-256 хэши релизных артефактов.** `SHA256SUMS` в корне — хэши всех
   10 CLI-бинарников (из `reproducible-build.sh --print`, побайтово
   воспроизводимая сборка) и 4 роутерных скриптов из `deploy/router/`.
5. **OpenTimestamps → Bitcoin.** `SHA256SUMS.ots` — независимое от GitHub и
   локальных часов доказательство существования этого набора хэшей на
   момент штампа. Календарные серверы (opentimestamps.org, eternitywall.com,
   catallaxy.com) агрегируют штампы в один Bitcoin-блок; подтверждение via
   `ots upgrade SHA256SUMS.ots` через несколько часов после коммита в
   блок. Держит доказательство даже если GitHub/аккаунт когда-либо
   станут недоступны.

## Осознанно НЕ принято (и почему)

- **Anti-debugger hooks, обфускация, самоуничтожение при несовпадении
  хэшей.** Такие меры годятся для продукта, который распространяется как
  закрытый артефакт и должен сопротивляться реверс-инжинирингу. Этот
  репозиторий — открытый (после публикации) AGPL-код, воспроизводимая
  сборка которого — это ЦЕННОСТЬ, а не то, что нужно скрывать.
  Обфускация буквально противоречила бы этому принципу проекта.
  Самоуничтожение — отдельный риск: `sovereign-core`/router-скрипты
  держат реальный self-heal с sudo-правами на системе, которая раздаёт
  интернет на дом. Ложное срабатывание (битый диск, прерванная запись,
  gray-area rebuild) должно ДЕГРАДИРОВАТЬ, а не убивать инфраструктуру.

  **Вместо этого:** `scripts/verify-integrity.sh` (ноутбук) и
  `/usr/bin/integrity-check` (роутер, cron `17 * * * *`) — считают
  SHA-256 развёрнутых артефактов, при расхождении шлют `CRITICAL` в
  syslog/journal и завершаются с ненулевым кодом. Ничего не отключают,
  не удаляют, не блокируют запуск. Обнаружение и алерт — правильный
  компромисс CIA-триады для этой системы: конфиденциальность и
  целостность важны, но доступность (интернет в доме) имеет вето на
  любое автоматическое деструктивное действие.

## Соотношение с остальными инженерными принципами проекта

Эти меры не заменяют существующие инженерные принципы проекта (zero-dependency
core, ACID/rollback, bounded no-panic execution, reproducible builds) — они
добавляют юридический и криптографический слой поверх них. Отдельный внутренний
документ (вне этого репозитория) уже фиксирует применимую часть этих мер
(self-tooling, проактивность, структурная память для будущих сессий); этот файл —
техническая реализация IP-защиты специфично для sovereign/sovds.
